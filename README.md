# Nymph

正式版与测试版的独立构建、校验和同一工坊条目发布流程见 [双分支发布说明](docs/dual-branch-release.md)。

《杀戮尖塔 1》NYMPH Mod 向《杀戮尖塔 2》迁移的独立纵向原型。

当前目标不是一次性复刻全部机制，而是先打通一条可反复扩展的链路：

`角色注册 → 初始牌组 → 初始遗物 → Godot 资源 → 游戏内战斗`

- 目标游戏：Slay the Spire 2 `0.109.0`
- 框架：STS2-RitsuLib `0.4.62`
- .NET SDK：`9.0.316`

- 角色：小笞心魔，75/75 生命，99 金币

- 初始遗物：探灵伯爵；纵向原型效果为每回合额外抽 1 张牌
- 思绪机制：每打出一张牌获得 1 点思绪；已支持创想、讲述与讲述全部
- 思绪计数器：使用塔一原图，并按清晰、混乱、阻滞切换绿、黄、红三种状态
- 已迁移卡牌：16 张，其中攻击 7、技能 6、能力 3
- 首批塔一卡牌：箱中祭器、知交笑语、思维重担、笞心魔的交心、
  生命熔炉之薪、狭路相逢、安魂祭礼、外传、心理暗示
- 已迁移能力：凋亡、外传、心理暗示
- 角色选择、地图、战斗、抽牌和出牌流程均已实机跑通

## 构建和运行
退出后台godot：在powershell运行
Get-Process Godot_v4.5.1-stable_mono_win64 -ErrorAction SilentlyContinue |
    Stop-Process -Force

直接双击或在终端执行：

```powershell
.\build.cmd
```

脚本使用仓库旁的便携 .NET 与 Godot，完成 C# 编译、PCK 导出，并部署到：

```text
D:\steam\steamapps\common\Slay the Spire 2\mods\Nymph
```

打开 Godot 工程：

```powershell
.\open-godot.cmd
```

本机路径放在被 Git 忽略的 `local.props` 中。换电脑时从
`local.props.template` 复制并修改游戏与 Godot 路径。

## 后续迁移批次

- 可继续直接迁移：普通伤害、格挡、创想、讲述、抽牌及原版力量/虚弱/易伤牌。
- 需要先补通用支撑：延迟回手、牌堆定向选择、保留成长、每回合思绪统计。
- 需要单独迁移体系：重构、年代、恐惧、临时生命、特殊选牌与跨战斗记录。
- 按当前范围暂缓：废弃卡、状态牌、灵感牌，以及依赖这些牌池的卡。

## 纵向原型中的临时实现

- 思绪已具有清晰、混乱、阻滞三个状态判定，但混乱/阻滞的伤害与格挡惩罚尚未接入。
- 探灵伯爵暂时使用“每回合额外抽 1 张牌”，灵感奖励池以后实现。
- 战斗人物使用静态资源；Spine 动画、音效和完整 VFX 尚未迁移。
- 卡框暂用 RitsuLib 默认材质，避免依赖已弃用的运行时着色 API。

这些边界是有意保留的：下一阶段可以逐项替换，而不必再次重做角色注册、
资源打包和部署环境。
